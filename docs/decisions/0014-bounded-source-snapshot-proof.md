# ADR0014 — Bounded source snapshot acquisition proof

Status: CP16 synthetic acquisition proof only; no Android media capture or provider transfer.

CP13 proves recovery for generated component manifests, and CP15 proves account-bound
asynchronous transfer recovery. Neither proves that a mutable source can be read into
one complete, immutable snapshot before transfer: CP13 receives generated bytes from
its fixture builder and captures an in-memory slice. Architecture §§7.2 and 10 require
source/component revisions to remain coherent while a selected original is prepared.

## Decision

Add a separate test-only protocol that acquires a bounded snapshot from a mutable,
generated stream source. An internally attested fixture inventory must state that it
is complete, identify exactly one primary and every supported companion component,
and bind each opaque source/version/component revision. Caller metadata, declared
hashes, filenames, URIs, and a UI selection token cannot mint this authority. Unknown,
partial, unsupported, or changed inventory denies the entire acquisition.

Read each generated component to EOF through an owned stream, enforce the test
bounds, compute actual length and SHA-256, and require successful close. Compare the
source and full component inventory before and after every component and again before
publication. Publish one opaque, immutable snapshot handle only when every component
passes. A failed read, changed revision, timeout, cancellation, stale session, or
uncertain close publishes no usable partial snapshot. Any lease that might still own
an unsettled read continues to block a competing acquisition until it is settled.

Snapshot bytes remain behind a private test-only handle. Public descriptors are
detached immutable copies and are explicitly `generated_synthetic_bytes` with
`synthetic_fixture_only` fidelity. No path, URI, media bytes, credentials, provider
handle, account label, or transfer receipt leaves the fixture adapter. Existing CP13
and CP15 contracts remain untouched; no SQL, journal, Android entry point, dependency,
UI, network, provider adapter, or production bootstrap is added. Test bounds are
harness limits, not user-facing photo size or component limits.

## Consequences and exclusions

This proves atomic acquisition semantics against generated mutable streams, not
Android's component inventory, original fidelity, durable staging, Google Drive,
transfer, verification, restore, or delete safety. MediaStore generations and UI
tokens remain observations, not canonical immutable versions. A later Android gate
must establish actual source-byte fidelity, companion discovery, permission/scope
fencing, storage limits and cancellation behavior before enabling any transfer.
OAuth configuration and device account consent remain independently required.

## Acceptance

Exercise complete generated primary/motion/sidecar snapshots; absent, unknown,
added, reordered and revised inventory; mutation in a later component and at final
publication; short/extra reads; actual length/hash mismatch; failed and unsettled
close; cancellation and stale-session completion; resource bounds; competing and
foreign handles; alias/accessor attacks; and retained effective guard-removal
counterfactuals. Every successful receipt remains test-only. No source or transfer
capability is thereby enabled.
